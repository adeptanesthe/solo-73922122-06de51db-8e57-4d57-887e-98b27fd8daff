# 推测解码验证台 + 人工偏好 DPO 微调台（Speculative Decoding & Preference DPO）

用 FastAPI + CPU 版 PyTorch 实现的网页应用，包含两个页面：

1. **推测解码验证台**（`/`）：验证推测解码能否在保证输出完全一致的前提下节省
   目标模型的前向调用，并验证被拒绝的草稿不会污染后续生成；
2. **人工偏好 DPO 微调台**（`/dpo`）：录入 1～8 组（提示词、优选续写、劣选
   续写）偏好样本，每次从原目标权重的深拷贝出发做 3 步整批均值 DPO，判断
   微调后模型是否更偏向优选续写；训练全程不改写原模型。

所有模型权重在进程内以固定随机种子生成，**无需下载任何模型**；词表为固定的 98 个
字符级 token，草稿与目标模型共用。

## 目录结构


## 模型设计（均为固定权重、确定性可复现）

| 模型 | 层数 | 注意力头 | d_model | 说明 |
|---|---|---|---|---|
| 目标模型 | 4 | 4 | 128 | 被核验的大模型 |
| 草稿模型 | 1 | 2 | 128 | 提议草稿的小模型 |

- 二者**共享 token 嵌入与 LM head（权重绑定）**，词表共用；
- 草稿主体在同一初始化 RNG 流之后，再用独立固定种子（seed=99）注入受控高斯扰动
  （σ=0.125）。该尺度经实测使两模型首 token 预测翻转率约 30%，从而同一服务内
  既能稳定观测到**整块接受**，也能稳定观测到**拒绝**；
- 完全独立初始化会导致未训练模型 argmax 近乎 100% 不同（几乎全拒绝），完全一致
  又不会拒绝，受控扰动是让两条路径都可演示的关键。

## 推测解码算法要点

1. 用户设置每轮草稿数 `k ∈ [1,4]`、最多新 token 数 `max_new ∈ [1,32]`；
2. 每轮草稿模型基于**自身 KV 缓存**逐 token 增量写出最多 `k` 个草稿；
3. **目标模型每轮只做 1 次前向**，整块核验草稿；首轮输入「提示词+草稿块」，
   之后每轮输入「上一轮 pending 的纠正/补词 token + 新草稿块」，
   **已缓存前缀绝不重算**；
4. 逐位比对目标贪心预测与草稿 token：
   - 拒绝：丢弃被拒位置及之后的草稿，采用目标在该位置的纠正 token，并把目标/草稿
     KV 缓存截断回滚到接受前缀（回滚无污染，有专项测试）；
   - 整块接受：额外采用目标基于整块上下文的补词 token；
5. `max_new` 上限与 EOS 截断在两条路径上语义完全一致（EOS 计入输出，其后停止）；
6. argmax 平局取词表序号小者（`torch.argmax` 返回首个最大值，天然满足）。

**缓存不变量**：每轮开始时目标缓存覆盖确认前缀倒数第二个 token，pending 保存上一轮
tail；草稿缓存对齐完整确认前缀。因此目标前向次数恒等于推测轮数。

## 正确性保证

推测解码输出在拒绝、整块接受、EOS、达到上限等所有情况下，都与「目标模型**无缓存、
逐 token、对完整前缀重算**的贪心基线」**逐 token 完全相同**。前端在不一致时会标出
首个分歧位置（token id 与文本）并判定 FAIL。

## 人工偏好 DPO 微调（`/dpo`）

### 输入约束与服务端版本管理

- 1～8 组偏好样本；每组的提示词、优选续写、劣选续写均为 **1～32 个可打印 ASCII
  字符**（空格 `0x20` 到 `~` `0x7E`），后端 `validate_pairs` 与前端计数器双重校验，
  非法保存返回 400 且不改动当前偏好集；
- 偏好集保存在**服务端**，带单调递增**版本号**与内容**指纹**（SHA-256 前 16 位）。
  任何一次保存（即使内容改回原值）都使版本号 +1；训练线程在结束时比对版本，
  版本变化则本次在途结果**永久废止**（状态 `invalidated`），改回内容也不恢复。

### 训练设定（固定超参数）

| 项 | 取值 |
|---|---|
| 起始权重 | 原目标模型的独立 `deepcopy`（每次训练重新拷贝） |
| 冻结参考 | 原目标模型的另一份 `deepcopy`，`requires_grad=False` |
| 步数 | 3 步整批均值 DPO |
| β | 0.1 |
| 优化器 | Adam，lr=0.001（其余为 PyTorch 默认 β1=0.9/β2=0.999/eps=1e-8） |
| 序列得分 | 仅累加**续写 token** 的条件 log-prob，提示词位置不计分，**不追加 EOS** |
| 损失 | `-logsigmoid(β·((π_w-π_l)-(π_ref_w-π_ref_l)))`，对全部对取均值 |

### 两条独立实现与交叉校验

1. **逐对梯度累积（生产路径）**：每对单独前向，损失除以对数后立即 `backward()`
   并释放该对计算图，任何时刻最多保留一对图，绝不保留多对图；全部对梯度累积后
   做一次 Adam 更新。
2. **独立整批参考（豁免"不保留多对图"限制）**：独立模型拷贝、独立 Adam、独立
   训练循环；每步全部对的前向图同时保留并收集整批均值损失；冻结参考/训练前得分
   走 padding 批量前向（单次批量调用算完全部序列）。

> 实测发现：批量 GEMM(B>1) 与单序列 GEMM(B=1) 的前向/反向存在 1e-8～1e-11 级
> float32 归约差异，经 Adam 在近零梯度处会被放大到 1e-4 级，无法满足 1e-5 容差。
> 因此两条训练路径统一采用同形状单序列前向、同一逐对反向顺序，使浮点运算逐位
> 一致；两条路径的差异落在 **autograd 图组织方式**（随建随释 vs 整批共存）与
> **打分代码路径**（单序列 vs padding 批量）上，这正是需求要求交叉校验的部分。
> 实测更新参数最大绝对误差为 **0.0（逐位相同）**，训练前两套打分误差同样为 0。

### 结果展示与失败保留

- 仅当训练**成功且交叉校验通过**（参数最大绝对误差 ≤ 1e-5）才展示：每组优选/劣选
  续写的训练前、训练后、冻结参考得分，优选-劣选间隔的前→后变化，每步两条实现的
  均值损失对照，以及参数误差；
- 训练失败或在途被废止时，**完整保留上次成功结果**，并用版本号、指纹、job_id 与
  输入摘要标明它属于哪一次输入；失败原因（含具体误差值）单独红字提示；
- 训练在后台 daemon 线程执行，同一时刻最多一个任务（重复启动返回 409）；训练期间
  两个窗口仍可编辑同一偏好集、运行 `/` 页的原解码对照。

### 原模型不变量

训练只对 `get_models()` 返回的目标模型做 `deepcopy`，**不调用原模型前向**，因此
原草稿/目标模型的权重、KV 缓存长度、前向计数在训练前后完全不变（有专项测试）。
微调产物只存在于当次结果中，不会回写单例模型，刷新页面后原模型行为依旧。

## 启动方式

### Docker Compose（推荐）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

镜像基于 `python:3.11-slim`，通过 PyTorch 官方 CPU index 安装
`torch==2.5.1+cpu`，不含 CUDA 依赖；带 `/api/health` 健康检查。

### 本地直接运行

```bash
pip install --index-url https://download.pytorch.org/whl/cpu torch
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 接口

- `GET /api/health`：服务与模型信息；
- `GET /api/presets`：返回固定的「拒绝」「整块接受」两条预设提示词；
- `POST /api/decode`：入参 `{prompt, k(1~4), max_new(1~32)}`，返回两种方式的
  token 序列、解码文本、目标/草稿前向次数、逐轮核验明细、节省统计与一致性判定；
- `GET /api/preferences`：服务端偏好集（版本号、指纹、更新时间、样本数组）；
- `PUT /api/preferences`：整体替换偏好集，入参 `{pairs:[{prompt,chosen,rejected}]}`；
  校验失败返回 400；成功则版本号 +1 并废止在途训练；
- `POST /api/dpo/train`：启动后台 DPO 训练；已有任务运行时返回 409；
- `GET /api/dpo/status`：训练状态机（idle/running/success/failed/invalidated）、
  在途任务信息、上次成功结果（带输入版本/指纹标注）与最近终态错误；
- `GET /dpo`：偏好 DPO 微调页面。

## 实测结果（CPU，torch 2.5.1+cpu，单线程）

- `python tests/test_decoding.py`：**10 项全部通过**（84 组参数组合下推测解码与
  贪心基线逐 token 一致，缓存回滚无污染，EOS/上限/平局行为正确，预设覆盖两种判定）；
- `python tests/test_dpo.py`：**14 项全部通过**，要点：
  - 输入校验覆盖 0/9 组、空段、33 字符、换行/Tab、非 ASCII 等全部非法边界；
  - padding 批量打分与单序列打分在同一 batch 内**逐位相等**；
  - 逐对路径每对 `backward` 后计算图立即释放（反向再访问报图已释放）；
  - 两条独立实现 3 步更新后参数最大绝对误差 **0.0 ≤ 1e-5**，训练前打分误差 0；
  - 训练后每组优选-劣选间隔均不劣于训练前（3 组示例分别 +143.7→+525.1、
    +300.0→+692.5、-297.2→-72.8），冻结参考得分与训练前得分逐位相等；
  - 训练前后原草稿/目标权重逐位相同、KV 缓存长度与前向计数零增量；
  - TestClient + 真实 uvicorn 双通道验证：保存→训练→轮询全流程、在途编辑废止
    （invalidated）且上次成功结果保留、模拟对照失败时保留上次成功、并发启动 409、
    训练在途时 `/api/decode` 对照仍 PASS。

> 说明：DPO 损失通常在第 2 步即降到 1e-5 以下——该未训练随机模型的续写 log-prob
> 绝对值很大（单序列长度短、logits 尖锐），β=0.1 下偏好间隔对应的 sigmoid 很快
> 饱和；这是机制演示，分数的相对变化（间隔改善）才是"更偏向优选"的判据。
